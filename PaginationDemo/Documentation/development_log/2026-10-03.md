# Development Log — 2026-10-03

## What we worked on today

- **Checkpoint 1 — Project Setup**: Set up a local database (Postgres, running in Docker) and created an `Item` table to store our data. Then filled that table with 2 million sample rows, so we'd have a realistically large dataset to test pagination against — not just a handful of rows.
- **Checkpoint 2 — Basic Pagination**: Built the first working version of the `GET /items` API. A client can now ask for a specific "page" of results (e.g. "give me page 2, with 5 items per page") instead of getting everything at once. The response also tells the client useful things like how many total items exist and whether there's a next page.
- **Checkpoint 3 — Sorting**: Added the ability to sort results, e.g. "show me the newest items first" or "sort alphabetically by name." To keep this safe, we only allow sorting by a small, approved list of fields — if someone asks to sort by a field we don't allow, the API clearly says so instead of breaking or doing something unexpected.
- Manually tested everything above using real requests (via curl and Postman) against the 2-million-row dataset to confirm it actually works, not just that it compiles.

## Decisions made

- We write out dependency wiring by hand instead of using a shortcut annotation — a little more typing, but it makes it obvious how pieces of the app connect to each other, which is better for learning.
- We only allow sorting by a short list of approved fields, rather than letting the client sort by anything. This keeps the API predictable and protects against accidentally slow or unsafe requests.
- Adding 2 million rows was done with a single bulk database command instead of inserting rows one at a time — much faster, and it mirrors how this would realistically be done outside a learning project.

## Known gap (expected, not a bug)

Right now, the API doesn't yet reject bad input — for example, asking for a negative page number or an unreasonably large page size. That validation is planned for the next checkpoint, not something we missed.

## Next up
