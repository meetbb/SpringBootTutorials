# Development Log — 2026-09-25

## What we worked on today

- Reviewed the system design and confirmed Checkpoints 1 and 2 were already done.
- **Checkpoint 3 — Registration Endpoint**: added `POST /auth/register` with validation, password hashing (`BCryptPasswordEncoder`), and duplicate-email checking.
- **Checkpoint 4 — JWT Utility**: added `JwtService` — generates and validates JWT access tokens, built and usable independent of the DB.
- **Checkpoint 5 — Login Endpoint**: added `POST /auth/login` — checks credentials, issues an access token via `JwtService`.
- **Checkpoint 6 — JWT Filter + Security Config**: added `JwtAuthFilter` and `SecurityConfig` — every request is now checked for a valid Bearer token; `/auth/register` and `/auth/login` stay public.
- **Checkpoint 7 — Protected Test Endpoint**: added `GET /auth/me` and proved the full chain works live — register → login → call `/auth/me` with the token → get data back; without a token, request is rejected.
- Added unit tests: `JwtServiceTest` (token generation/validation/tampering/expiry) and `UserServiceLoginTest` (login success + two failure cases).
- Ran a live end-to-end test using Docker (Postgres + Redis) and the running app — confirmed the whole register → login → `/auth/me` flow works correctly.
- Discovered a known rough edge: unhandled exceptions currently surface as an empty `403` instead of a real error, because of how Spring forwards errors through our security filter. This is expected to be fixed at Checkpoint 10, not before.

## Decisions made

- Constructors are written by hand everywhere (no `@RequiredArgsConstructor`), to keep dependency injection visible and explicit for learning purposes.
- Tests are only added when explicitly asked, never automatically.
